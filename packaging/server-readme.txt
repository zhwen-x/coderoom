CodeRoom 判题服务端（教师端）
=============================

★ 第一次使用，先做这一步
   双击同目录的「放行防火墙.cmd」，按提示允许管理员权限，运行一次即可。

   Windows 防火墙默认拦截新程序的入站连接。不做这一步，服务端看起来一切
   正常（照常监听、照常显示局域网地址），但没有一台学生机连得上。
   只需做一次，换端口也不用重做；把整个目录挪到别处后需要再做一次。
   服务端启动时会自检，未放行会在横幅中提示。

日常使用
--------
1. 双击 coderoom-server.exe，窗口会显示教师端网址和管理口令。
2. 浏览器会自动打开教师端；管理口令请勿转发给学生。
3. 窗口中列出的 "IP:端口" 就是告知学生端的服务器地址。
4. 数据全部保存在同目录的 coderoom-data 文件夹，整个文件夹可直接拷贝备份。
5. 启动横幅会写明「可判语言」。若缺少 C++/C/Python，说明本机没有对应的
   编译器，可在教师端「系统 - 判题环境」中手动指定路径，或把便携工具链放到：
      toolchain\mingw64\bin\g++.exe
      toolchain\python\python.exe
6. 判题使用的语言标准在教师端「系统」中设置（默认 C++14 / C11）。
7. 判题在 Windows Job Object 沙箱中运行：限制内存、CPU 时间和进程数，
   并抑制崩溃对话框。详见教师端「系统 - 判题沙箱」。

考场行为监控
------------
新建的"考试"默认开启：U 盘/存储设备、黑名单进程、前台窗口、粘贴留痕。
新建的"练习"默认只开粘贴留痕（练习时查资料是正常学习行为）。
外网连接监控默认关闭，它噪音最大，需要时再手动打开。

要改：考试/练习 → 选中这一场 → 控制 → 监控策略 → 编辑。
考中也能改：保存后策略版本号 +1，全班学生端在一次心跳内（默认 10 秒）
各自把新策略拉下来，不需要逐台操作，也包括那一刻还没开机、之后才重启的机器。

看板：监考页。上半是在线学生（在线状态 / 当前前台程序 / 告警计数 /
最后心跳 / 交卷时间），下半是实时事件流。点学生这一行可只看他的事件时间线。

几点需要知道的边界：
  - 白名单里默认含极域电子教室和机房 IDE（VS / Dev-C++ / PyCharm / IDLE）
    与控制台。学生本来就该待在 IDE 里，把这些当异常会把真正的告警淹掉。
    改白名单时请留着它们。
  - 前台窗口要停留 20 秒以上才上报，短暂切换（点任务栏、自己的程序弹控制台）
    不会产生记录。学生运行自己编译出来的程序时间较长，可能出现一条记录。
  - 进程黑名单按程序名整名匹配，大小写和 .exe 后缀都无所谓，但不做子串匹配：
    填 QQ 不会命中 QQBrowser.exe（它单独列了一条）。学生把 chrome.exe 改名
    就能绕开这一项，前台窗口标题仍然会留痕。
  - 若某台机器报告"监控项不可用"，说明那台客户端做不了这项检查，不要当成
    那台机器很干净。
  - 客户端失联（学生强退进程）由服务端发现：45 秒没有心跳记一条告警，
    一次失联只报一次。仅对"进行中的考试、尚未交卷的学生"生效。

强制管控（禁 U 盘 / 断外网）
----------------------------
默认关闭，要用就在「监控策略」对话框下半部分打开。

★ 前提：学生端必须以管理员身份运行。
   没有管理员权限的机器不会被管控，监考看板的「管控」列会标红「无法管控」
   ——程序不会假装锁上了。开考前扫一眼这一列，就知道哪几台没锁住。

它具体做什么：
  禁 U 盘   停止加载 USB 存储驱动。注意：已经插着的 U 盘不会被弹出
            （驱动已加载），拔掉后才无法再用。监控仍会记录它。
  断外网    只封锁公网地址，局域网全部放通。判题服务端、极域电子教室、
            文件共享、打印机都照常可用，断的只是外网。

★ 恢复有多重保障，任何一条路出问题都不会把机器锁死：
   1. 正常情况：考试结束 / 学生交卷登出 / 关闭客户端 / 你改了策略 —— 自动恢复
   2. 学生强行结束客户端进程 —— 看门狗进程立即恢复（实测 0.7 秒）
   3. 学生结束整个进程树（连看门狗一起杀）—— 每分钟运行一次的计划任务
      恢复（实测 44 秒）
   4. 机器断电重启 —— 开机计划任务（以 SYSTEM 运行）自动恢复，不需要有人登录
   5. 你在控制面板点「紧急解除管控」 —— 全班在 10 秒内恢复，监控不受影响
   6. 以上都失败：在那台学生机上运行
         coderoom-client.exe -restore
      它不需要服务端、不需要登录，直接把 U 盘与网络还原后退出。

   另外，一旦过了交卷时间，客户端即使联系不上服务端也会自己解除管控。

   ★ 机房装了还原卡 / 冰点还原 / 共享盘保护的，在「监控策略」里勾上
     「机房重启会自动还原系统」。勾上之后不再创建上面第 4 条的开机恢复任务
     ——在这类机房里它本来也跑不起来，还原会把计划任务本身一起抹掉，而重启
     本身就已经把管控还原了。其余各条全部保留。
     不确定就别勾：多装一个计划任务没有任何坏处。

   如果某台机器曾被遗留的管控恢复过（说明它上次是崩溃或断电结束的），
   会在事件流里出现一条「发现并恢复了遗留管控」的提醒。

一场考试的大致流程
------------------
题库建题并上传测试数据 → （可选）组卷建模板并预览 → 系统导入名单
→ 新建考试 →（按需调整监控策略与强制管控）→ 发布（学生可登录，看不到题面）
→ 开考（下发题面、开始倒计时）→ 考中看监考页
→ 结束 → 对账（处理有代码但没提交的学生）→ 全部重判 → 公布成绩
→ 成绩页导出 CSV、对账页导出代码 zip

同一场想再跑一遍（练习尤其常见）：直接点「发布」。结束过的场次重新发布时，
上一轮的开考与结束时间会被清掉，下次开考重新计时；原有成绩与提交记录保留。
