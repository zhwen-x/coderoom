# CodeRoom

局域网编程判题系统（类 OJ），供教学练习与上机考试使用。教师端一个 exe，学生端一个 exe，免安装、绿色运行。

当前进度：**M4 已完成**。业务闭环可用，判题运行在 Windows Job Object 沙箱中，支持随机组卷与每人一卷、考后对账补交、代码打包导出；考场行为监控（U 盘、黑名单进程、前台窗口、外网连接、粘贴留痕、客户端失联）与实时监考看板已可用；考试期间可强制禁用 U 盘存储与外网访问，并带五重自动恢复。

目标环境：Windows 10 机房，学生使用 Visual Studio / Dev-C++ / PyCharm / IDLE 编写代码。

## 快速开始

### 开发/测试（macOS、Linux）

```bash
go test ./... && go vet ./...
```

```bash
go run ./cmd/coderoom-server -addr :8080 -data ./coderoom-data
```

服务端启动后会打印教师端网址（含管理口令）和告知学生的局域网地址。学生端：

```bash
go run ./cmd/coderoom-client -server 127.0.0.1:8080
```

非 Windows 主机上，学生端界面会在默认浏览器中打开（开发模式）；Windows 上是独立的 WebView2 窗口。

### 构建 Windows 发行包

在 macOS / Linux 上交叉编译：

```bash
./scripts/build.sh
```

在 Windows 上原生编译（双击 `scripts\build.cmd`，或在终端里）：

```
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

两者产物一致：`dist/server/` 与 `dist/client/`，各含 64 位与 32 位 exe 和一份中文说明，
服务端包另附可双击的「放行防火墙.cmd」；构建前都会做前端语法检查、`go vet` 和单元测试，
并在 `toolchain/` 非空时把便携工具链折进服务端包。

**在 Windows 上构建多一层价值**：`go test` 会真实执行判题沙箱的代码路径（`NewRunner()`
在 Windows 上返回的就是 Job Object 实现），这是交叉编译验证不到的。

PowerShell 脚本的常用开关：

| 开关 | 作用 |
|---|---|
| `-SkipTests` | 跳过 vet/test，仅反复调试构建本身时用 |
| `-Arch amd64` | 只构建 64 位，省一半时间 |
| `-Out <目录>` | 改变产物目录 |

`build.cmd` 只是一层包装：绕过 PowerShell 对未签名脚本的默认执行策略，并在结束时
`pause`，这样双击运行出错时窗口不会一闪而过。

### 命令行参数

服务端 `coderoom-server`：

| 参数 | 默认 | 作用 |
|---|---|---|
| `-addr` | 配置文件中的值（首次为 `:8080`） | 监听地址 |
| `-data` | exe 同目录的 `coderoom-data` | 数据目录（数据库、测试数据、学生代码） |
| `-workers` | 配置文件中的值（首次为 2） | 判题并发数 |
| `-open` | `true` | 启动后自动打开教师端 |
| `-setup-firewall` | — | 添加防火墙入站规则后退出，需管理员权限（见下文） |

学生端 `coderoom-client`：

| 参数 | 默认 | 作用 |
|---|---|---|
| `-server` | 空 | 直接指定服务端地址，跳过自动发现 |
| `-data` | exe 同目录的 `coderoom-client-data` | 本机数据（草稿、待上报事件、导出的答卷） |
| `-discovery-port` | `8099` | 自动发现使用的 UDP 端口，需与服务端一致 |
| `-no-window` | `false` | 不开窗口，只跑本地服务；诊断与自动化测试用 |
| `-restore` | — | **解除本机残留的考场管控后退出。**考试异常中断时的手动兜底，不需要服务端 |
| `-watchdog` | — | 内部使用：由客户端自己拉起，监视主进程，其退出后立即解除管控 |

## 一场考试是怎么跑的

教师端（浏览器）：

1. **题库** → 新建题目，填题面并上传测试数据。没有测试数据的题目不会被随机抽中。
2. **组卷**（可选）→ 建模板，每个题位选「指定题目 / 题目池 / 按条件筛选」。
   点「预览组卷」确认能正常出题——这一步能把考中故障变成考前提示。
3. **系统** → 导入学生名单（可从 Excel 直接粘贴）；确认「可判语言」齐全。
4. **考试/练习** → 新建。题目来源选手动选题或组卷模板；选了模板才能开「每人一卷」。
   练习是即时判题、可重复提交；考试的成绩要等教师公布。
5. 考试的**监控策略**默认已开启 U 盘、黑名单进程、前台窗口、粘贴留痕（练习默认只留粘贴留痕）。
   要改就在「考试/练习 → 控制 → 监控策略 → 编辑」里改，**开考后改也可以**：保存后全班在一次
   心跳内自动应用。
   同一个对话框里还有**强制管控**（禁 U 盘 / 断外网），默认关闭。打开它需要学生端以管理员身份
   运行；做不到的机器会在监考看板上标红，不会假装锁上了。出任何问题，控制面板上的
   **紧急解除管控**一键放开全班。
6. 点**发布**，学生可以登录了，但看不到题面。到点后点**开考**，题面下发、倒计时开始。

学生端：

7. 双击 exe，自动发现服务端（发现不到就手动输入教师给的地址），输入学号姓名进入。
8. 在机房 IDE 里写好并自测，粘贴进内嵌编辑器，点「保存」存本机、点「提交判题」上交。
   代码每 30 秒自动快照上传一次，网络断了也不会丢。
   启用了监控时，标题栏显示「监考中」，点「更多」能看到本场具体开了哪几项。

教师端（考中）：

9. **监考**页。上半是在线学生表：在线状态、当前前台程序、**管控是否真的生效**、告警计数、
   最后心跳、交卷时间；
   下半是实时事件流（SSE 推送，不是轮询刷新，所以不会在你读到一半时整表重建）。
   点任意一行只看这名学生的事件时间线，点「看全部」退回。

教师端（考后）：

10. 点**结束**。**对账**页会列出缺考、有代码但没点提交、部分未答的学生；
   「有代码未提交」的可以逐人用最后一次快照补交，补交会标注来源。
11. 点**全部重判**（改过测试数据时需要），再点**公布成绩**让学生可见。
12. **成绩**页导出 CSV，**对账**页导出全部代码的 zip。

想再跑一遍同一场（练习尤其常见）：直接点**发布**。结束过的场次重新发布时会清掉
上一轮的开考与结束时间，下次开考重新计时；成绩和提交记录保留。

## 系统组成

```
教师机（coderoom-server.exe，单文件 ~11MB）
  浏览器打开启动横幅给出的带口令网址  ← 内嵌教师端 Web 控制台
  考试/练习 · 题库 · 组卷 · 监考 · 提交 · 成绩 · 对账 · 系统
  SQLite(WAL) + 文件存储（测试数据 / 学生代码全量留痕）
  判题队列（落库，可重启恢复）→ worker 池 → 编译 + 跑测试点 + 比对
        ▲ HTTP/JSON                    ▲ UDP 广播自动发现
学生机（coderoom-client.exe，单文件 ~7.5MB）
  WebView2 窗口 ← 本地回环 HTTP 服务 + 内嵌界面（自写高亮编辑器，零依赖）
  后台：定时快照上传 · 心跳+策略同步 · 行为事件上报 · 本地持久化队列
```

无需安装运行时、无需配置数据库、无需 npm 构建链。直接依赖只有三个纯 Go 库
（`modernc.org/sqlite`、`jchv/go-webview2`、`golang.org/x/sys`），全都不需要 CGO，
因此可在 macOS 上一条命令交叉编译出 Windows 可执行文件。

## 几个决定了架构的设计点

**策略由客户端拉取，而不是教师端推送。** 机房现有的极域电子教室有两个已知缺陷：教师端开启限制时若学生机尚未进入系统则该机漏网；学生机重启后限制失效。两者的共同根因是单向推送。本系统反过来做：客户端登录时取策略，之后每次心跳带上自己的 `policy_version`，服务端发现过期就下发新策略。学生机无论何时开机、重启几次，客户端一起来就会自动收敛到当前策略。教师在考中改监控策略同样走这条路：保存即 `policy_version` +1，全班在一次心跳内（默认 10 秒）各自拉到新策略，不需要逐台操作。M4 的强制管控也走同一条路：教师点「紧急解除管控」时，服务端把两个拦截开关置假并把版本号 +1，全班在一次心跳内各自恢复——紧急通道和日常通道是同一条，不存在"真要用的那天才发现它坏了"的第二套机制。

**代码由客户端推送，而不是服务端拉取。** "服务端定时收取代码"如果做成服务端主动拉取，就要求学生机开监听端口，会被 Windows 防火墙拦。做成客户端定时推快照，既穿透友好，又顺便产生了完整的编辑时间线。

**服务端时间是唯一权威。** 客户端本地时钟、学号姓名、客户端进程本身都假定可被篡改。倒计时只用服务端时间；本地时间仅作为证据记录，偏差过大本身是一条告警事件。学生强退客户端无法自我上报，所以由服务端侧的心跳超时来发现。

**代码先落本机，再上传。** 任何一次保存都先写本机磁盘（写临时文件再 rename，断电不会留下半截文件），上传失败就保持 dirty 等下个周期重试。考试末尾网络故障时，还有"导出本机答卷"作为人工补交的兜底。

**粘贴留痕取代禁止粘贴。** 学生在机房现有 IDE 里写代码再粘贴进来，所以剪贴板不能禁用。改为记录每次粘贴的字符数、行数和时间，异常粘贴上报为告警事件；配合全量快照时间线，可以看出代码是逐步写出的还是一次成型的。

**管控的难点是保证一定能解，不是怎么禁。** 这是全项目风险最高的一段代码，而风险不在于学生钻空子，在于考完之后机房里留下一台没有 U 盘、没有网络、教师也修不回来的机器。五十台变砖是事故，一次没抓到的手机查询不是——所有设计都从这个不对称推出来：

- **所有失败路径一律 fail open。** 崩溃、被强杀、断电、服务端失联、考试过期，结局都是恢复，绝不是保持锁定。
- **先写恢复记录，再改机器。** 账本（原始值）落盘并 `fsync`、开机恢复任务装好，之后才动第一个设置。顺序反过来的话，中间断电就会留下一台锁着的机器，而机器上没有任何东西知道怎么解锁。
- **启动时无条件恢复，再按需重新应用。** 判断"这把锁是不是还合法"需要服务端，而服务端正是可能联系不上的那个。
- **五层解除**：正常释放（考试结束/登出/退出/策略变更）→ 看门狗（客户端被强杀）→ 开机计划任务（断电重启，以 SYSTEM 运行，不需要有人登录）→ 教师端紧急解除 → 学生机上手动 `coderoom-client.exe -restore`。
- **还有一层不需要服务端**：过了交卷时间就自动解除。如果服务端在考中挂掉，客户端永远收不到"考试结束"，这一条是唯一能在完全离线时把机器放出来的路径。

**断网用加规则，不用改默认出站策略。** 翻转默认出站动作意味着恢复时要忠实还原一组多值设置（入站动作、通知抑制、三个配置档），弄错一次就永久削弱了这台机器的防火墙，而且没人会发现。加两条固定名字的规则、恢复时按名字删掉，不可能删一半，也不用解析 netsh 的本地化输出。封锁范围是"私网之外的所有地址"：Windows 防火墙里 block 规则优先于 allow 规则，所以"全封再放行服务端"根本不成立；而放通整个局域网正是机房要的——判题服务端、极域、文件共享照常，只有外网断。

**禁 U 盘恢复的是读到的原值，不是硬编码的"启用"。** 机房镜像里本来就禁了 U 盘的机器，考完必须还是禁的。

**没有管理员权限就明说，不假装。** 客户端会检查是否提权、并真的试着打开注册表键（组策略锁定的机器提了权也写不进去）。做不到就在监考看板上标红「无法管控」并上报告警——让教师以为整间机房锁好了而实际没有，比不锁更糟，因为他们要到看成绩时才会知道。

**行为监控的难点是噪音，不是检测。** 枚举进程和读前台窗口都是几行代码；难的是让看板上剩下的每一条都值得教师走过去看一眼。一个会对正常行为报警的监控项，会训练监考老师忽略整块看板——那比没有这个监控项更糟，因为考场看起来被监督着，实际没有。所以每条规则都偏向沉默，且理由都写在 `internal/client/monitor.go` 对应位置：

- **白名单里主要是「正常流程」，不是「例外」。** 学生本来就该待在 Dev-C++ / VS / PyCharm / IDLE 里写代码再粘过来，所以机房 IDE 和控制台全部在默认白名单内；极域电子教室也在，它的广播教学会同时抢走全班的前台。
- **前台窗口要停留 20 秒以上才上报。** 点一下任务栏、自己的程序弹个控制台、编译完成切回来，都在阈值以下。同一个程序两分钟内不重复上报，所以来回 alt-tab 产生一条记录而不是四十条。
- **「当前前台」走心跳，不走事件。** 看板上那一列回答的是"他现在在哪"，不花任何事件代价；事件回答的是"他去过哪"。
- **进程黑名单整名匹配，不做子串匹配。** 教师填 `QQ` 不会命中 `QQBrowser.exe`（那是单独一条），大小写和 `.exe` 后缀都无所谓。
- **外网监控默认关闭。** Windows 自己一直在联网，系统进程过滤表是按进程名排除的，不是真正的身份校验。这一项噪音最大，要教师明确打开、并且确实打算看它的输出。
- **时钟偏移按「变化」上报，不按心跳上报。** 一台时间本来就不对的机器，整场考试只产生一条记录；考中真的改了时钟才会再产生一条。

M3 的 Windows 侧已在实机验证过：手写的 `MIB_TCPROW` 结构偏移用测试进程自己建立的 TCP 连接做 ground truth 反查（IPv4 与 IPv6 各一次）；窗口标题用测试自建的隐藏窗口校验 UTF-16 往返（标题含中文）；`GetVolumeInformationW` 两个分支都跑到了——这一个调用决定了 U 盘到底会不会被发现，弄错了的表现是"每块移动盘都报告成空卡槽，永远不出事件，日志里也看不出来"。端到端：真实客户端连真实服务端，新增盘符与黑名单进程都在看板上出现，进程连续运行 36 秒（约 12 次轮询）只产生一条告警。

**监控项跑不起来必须明说。** 如果策略要求监控 U 盘而这台机器做不到（比如非 Windows 的客户端），客户端会上报一条 `monitor_degraded`。**一台没在监控的机器，绝不能和一台干净的机器长得一样**——看板上的沉默必须只有一种解释。

**失联告警只能由服务端发出。** 事件日志里其他所有内容都是客户端自报的，而强退客户端的学生恰恰安静下来——安静也正是守规矩的学生的样子。服务端每 10 秒巡检一次心跳，超过 45 秒没动静就记一条告警，并用会话上的一个闩锁保证**一次失联只报一次**，恢复后再断才会再报。范围被刻意收窄到「进行中的考试、尚未交卷的学生」：练习里关掉客户端只是离开，考试结束时全班同时掉线，这两种情况报警只会刷屏。

**组卷模板描述的是规则，不是题目。** 一个模板由若干「题位」组成，每个题位三选一：指定题目、从教师圈定的题目池里抽一道（适合针对某个知识点）、或按难度与标签筛选后抽一道。难度固定在题位上，所以每个学生的第 N 题难度相同——这是让每人一卷的成绩仍然可比的关键。抽取结果在同一份卷内不重复，且**没有测试数据的题目永远不会被随机抽中**（抽到了学生就答了一道判不了的题），固定指定的则尊重教师选择但会告警。

**每人一卷在学生首次登录时生成，而不是考前按名单批量生成。** 这样自由输入模式和临时到场的学生都能正常考试，不需要事先存在于某张名单里。抽取对 (模板种子, 考试, 学号) 确定性成立，所以客户端重启拿回的是同一份卷，不会中途换题；教师想换一批题可以「重新随机」，它改的是模板种子。

**组卷模板必须能在考前验证。** 「某个筛选条件匹配不到题目」如果在开考时才暴露就是事故。教师端的「预览组卷」会显示每个题位的可选题数、示例题目，并模拟抽取几份卷——这把一个考中故障变成了一条配置提示。

**考后对账把「学生写了代码但忘了点提交」变成可修复的。** 定时快照本来就在收，所以服务端知道谁有代码却没有终稿。对账报表把这类学生排在最前，教师可以逐人用最后一次快照补交。补交是修复而不是捷径：已有终稿时拒绝，记录来源快照 id，写入操作日志，成绩单上标注「教师补交」——分数绝不会与学生实际交的东西悄悄不同。刻意不做批量补交按钮，否则会把学生主动放弃的草稿也一并交上去。

**判题沙箱的边界是明确的。** Windows 上每次运行都在独立的 Job Object 中，限制内存上限、CPU 时间、单进程（防 fork 炸弹），并抑制崩溃对话框——没有最后这项，一个崩溃的提交会弹出模态框把判题卡死到墙钟超时。还禁用了剪贴板、桌面切换和 ExitWindows。**不含文件系统隔离**：提交仍能读写服务端账户可及的文件，关掉它需要受限令牌或 AppContainer，列在 M5。防的是意外（死循环、内存耗尽、输出爆炸、误开子进程），不防刻意编写的恶意代码；考试场景下每份提交都与学号绑定、可追责，这个权衡是有意的。教师端「系统 → 判题沙箱」会原样显示当前平台实际生效的内容。

进程创建用 `CREATE_SUSPENDED`，先加入 Job 再恢复主线程，所以不存在"学生代码先跑了一会儿才被约束"的窗口。编译器被显式豁免于内存和进程数限制——gcc 本就要用几百 MB 并派生 cc1plus/as/ld，套用学生程序的限制会让所有提交编译失败。

## 目录结构

```
cmd/coderoom-server/    教师端入口（启动横幅、数据目录、信号处理）
cmd/coderoom-client/    学生端入口（窗口宿主、本地服务）
internal/protocol/      客户端与服务端共享的协议类型，含策略定义
internal/store/         SQLite 持久化 + 测试数据/代码的磁盘布局
internal/judge/         编译、运行、比对、评分（Runner 接口后面是平台沙箱实现）
internal/server/        HTTP API、判题 worker 池、UDP 发现、内嵌教师端 Web
internal/client/        上游 API、本地状态与离线队列、本地 HTTP、内嵌学生端 Web
scripts/build.sh        在 macOS/Linux 上交叉编译 Windows 发行包
scripts/build.ps1       在 Windows 上原生编译（测试会真实跑到 Job Object 沙箱）
scripts/build.cmd       build.ps1 的双击入口
packaging/              发行包附带的中文说明，两个构建脚本共用以免文案漂移
toolchain/              便携编译器的放置位置（二进制不入库，仅保留布局说明）
```

两处逻辑在客户端和服务端各实现了一份（代码哈希、源文件扩展名），由
`internal/client/hash_consistency_test.go` 跨包断言二者一致——这样客户端不必链接服务端的 SQLite 驱动。

### 判题环境

服务端判题需要 g++/gcc/python。三种来源，按优先级：教师端「系统」里手动指定的路径 →
发行包内的便携工具链 → PATH。启动横幅会直接写明「可判语言」，缺哪种一目了然。

便携工具链的目录布局见 [`toolchain/README.md`](toolchain/README.md)；放好后重新执行构建脚本
（`build.sh` 或 `build.ps1` 均可），它会被打进发行包，教师机无需安装任何东西。

判题使用的语言标准在教师端配置（默认 C++14 / C11）。机房的 Visual Studio、Dev-C++
与本项目的 gcc 并非同一编译器，但课程代码不涉及语言最新特性或 IDE 特有语法，
因此只要标准不比机房 IDE 更新就不会出现"学生本地能编译、服务端 CE"。
填入无法识别的标准会回退为默认值并告警，不会让整场考试的提交全部编译失败。

### 从源码构建时的两个环境问题

这两个都是在实机上碰到的，不影响发行包的使用，只影响从源码构建：

- **Go 不在 PATH 上**：`build.ps1` 会自动在常见位置查找并给出把它加进 PATH 的确切命令。
- **`proxy.golang.org` 不可达**：国内网络下拉取依赖需要换代理：

  ```
  $env:GOPROXY = "https://goproxy.cn,direct"
  ```

## Windows 防火墙（部署必读）

**这是实机测试中最重要的发现。** Windows 防火墙默认拦截新程序的入站连接：服务端会正常监听、
横幅会正常显示局域网地址，但**每一台学生机都连不上**，TCP 与 UDP 自动发现端口都被挡。
在机房里，这会在开考前才暴露。

服务端启动时会自检并在横幅中给出提示。发行包里附了可双击的「放行防火墙.cmd」，
它会自行申请管理员权限（资源管理器的「以管理员身份运行」没法传参数）；
从源码跑的话等价于：

```
coderoom-server.exe -setup-firewall
```

规则按**程序**授权而不是按端口，所以换端口后依然有效。自检同时校验规则里记录的程序路径与
当前 exe 是否一致，因此把目录移动后也能发现并重新提示。
